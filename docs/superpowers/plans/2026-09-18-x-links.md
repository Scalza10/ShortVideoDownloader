# X / Twitter links on the pile

> Approved plan, as executed. Review fixes changed some details afterwards (one spelling per tweet, a cap of 9, the title's t.co links, the queue check before counting); `docs/superpowers/specs/2026-09-18-x-links-design.md` is current.

## Context

The pile only accepts Instagram and TikTok links. People also want to paste X (Twitter) links and get the video. The video sits inside a tweet, so we have to pull it out of the tweet. Decisions made with the user:

- **A tweet with several videos adds each video as its own reel.** This includes the video of a quoted tweet.
- **"Fixer" links** (fxtwitter.com, vxtwitter.com, fixupx.com, fixvx.com) are rewritten to x.com and work like normal links.

What yt-dlp already does (checked in `.venv/.../yt_dlp/extractor/twitter.py`, pinned 2026.8.19):
- `TwitterIE` handles `x.com`, `twitter.com` and their `www.`/`m.`/`mobile.` hosts: `/<user>/status/<id>[/video/N]` and `/i/status/<id>`.
- Its playlist entries are the tweet's videos and GIFs, then the quoted tweet's, then card videos. One video → a plain video; several → `playlist_result`.
- Public tweets work without logging in (guest token). NSFW or protected tweets raise `login_required` with a "--cookies" hint, which already maps to `login_required`.
- Error messages we don't map yet: `No video could be found in this tweet`, `Media #N is not a video`, `Twitter API says: This Post was deleted…` / `…suspended account`.
- **A tweet with no video but a link is followed to the linked site** (`url_result(expanded_url)`). Without a guard, a tweet that links to YouTube would download the YouTube video, which gets around our allow-list.
- The `description` is the full tweet text and ends with the media's `t.co` link.
- **Why not `/video/N` URLs for the extra videos:** X's `/video/N` counts photos too, and can't address a quoted tweet's video or a card video. So we use yt-dlp's `playlist_items` on the tweet URL instead, which indexes exactly the entries above.

This is architectural (one paste can now create several jobs), so per the repo's process the design below is saved as `docs/superpowers/specs/2026-09-18-x-links-design.md` and committed first (`docs:`). Then come small `feat:` commits, TDD.

## Design

### 1. URLs (`reels_api/urls.py`, `models.py`)
- `Source.X = "x"` (the job JSON's `source`, an additive new value).
- `ALLOWED_HOSTS` gains `x.com`, `twitter.com`, each with `www.`, `m.`, `mobile.` → `Source.X`. `t.co` stays **not** allowed (it can redirect anywhere).
- New `normalize_url(url) -> str`: if the host is a fixer host (`fxtwitter.com`, `vxtwitter.com`, `fixupx.com`, `fixvx.com`, or any subdomain of one, e.g. `d.fxtwitter.com`), swap the host for `x.com`. Keep the scheme, path and query. Anything else is returned unchanged. `JobManager.submit` becomes `url = normalize_url(extract_url(text))`.

### 2. Errors (`models.py`, `downloader.py`)
- New `ErrorCode.NO_VIDEO = "no_video"`, message "This post has no video."
- `_ERROR_PATTERNS` (still ordered, first match wins):
  1. `NO_VIDEO`: `"no video could be found"`, `"is not a video"`, `"no suitable extractor"`. The last one is what the X guard below produces for a text tweet with a link, or for a profile/home link.
  2. `LOGIN_REQUIRED` (unchanged, must stay before "not available").
  3. `PRIVATE_OR_REMOVED`: add `"deleted"` and `"suspended"`.
  4. `UNSUPPORTED_URL`, then the `PLATFORM_BLOCKED` fallback (unchanged).
- `UNSUPPORTED_URL` message becomes "Only Instagram, TikTok and X video links are supported."

### 3. Downloader (`reels_api/downloader.py`)
- A shared `_base_opts(url, cookies_file)` holds today's quiet, timeout and cookie options. **For X URLs only** it adds `allowed_extractors: ["twitter", "twitter:card", "twitter:amplify"]` (yt-dlp fullmatches these case-insensitively). This stops the "follow the tweet's link to another site" path. Instagram and TikTok keep the default extractors, so nothing changes for them.
- `download(url, dest_dir, cookies_file=None, item=1)`: `playlist_items` becomes `str(item)`. The existing `entries[0]` handling already covers a one-entry playlist.
- New `count_videos(url, cookies_file=None) -> int`: `extract_info(url, download=False, process=False)`. If it's a `playlist`, count its non-empty entries, capped at `MAX_VIDEOS_PER_POST = 8`. Otherwise 1. **Any exception → 1**, so the normal job reports the real error through the usual path.
- Caption: strip trailing `https://t.co/…` links from the description (a regex anchored at the end). This does nothing for Instagram/TikTok.

### 4. Jobs (`models.py`, `pipeline.py`, `jobs.py`, `routes.py`)
- `Job.item: int = 1`, the playlist index to download. It is not added to the job JSON.
- `Pipeline` gets an injectable `counter` field (default `downloader.count_videos`) and a method `count_videos(url) -> int` that passes `settings.cookies_file`. `run` calls `self.downloader(job.url, temp_dir, cookies, item=job.item)`.
- `JobStore.find_active_by_url(url)` → returns **all** non-failed jobs for that URL, sorted by `item` (an empty list if none).
- `JobManager.submit(text) -> list[Job]`:
  1. normalize, extract, `detect_source`
  2. if active jobs for the URL exist, return them (a repeat paste is instant, with no network)
  3. `count = 1`; for `Source.X`, if the pipeline has `count_videos` (the fake pipelines in tests and dev_board may not; use `getattr`), run it via `asyncio.to_thread` under `asyncio.wait_for(COUNT_TIMEOUT_SECONDS = 20)`. A timeout or error counts as 1.
  4. check for active jobs again after the await (guards against a double tap during the count)
  5. if the queue lacks room for `count` jobs, raise `TOO_MANY_JOBS`
  6. create jobs `item=1..count`, all with the same URL, add them, queue them, return them
  - Partly failed tweets: a repaste returns the surviving jobs and doesn't retry the failed ones (same "failed jobs don't block" rule, kept simple).
- `POST /jobs` → `{"id": first.id, "status": first.status, "ids": [all ids]}`. `ids` is additive, and curl clients that read `id` keep working.

### 5. Page (`reels_api/static/`, `pages.py`)
- `format.js` `SOURCE_NAME` and `pages.py` `SOURCE_NAMES` gain `x: "X"`, so the board line reads "X · 0:19 · gone in 6h" and the preview "X · 0:19". `pages.py` indexes the dict, so this is required.
- `paste.js`:
  - hints: `no_video: "there's no video in that one."`; `login_required` becomes platform-neutral: "that one needs a login."
  - after `createJob`, take `ids = created.ids || [created.id]`, tell the board about the extra tiles (`onMore(ids.length - 1)`), and poll every id in parallel. Each done job → `onDone(job)`, each failed one → `onFail()`, so tiles fill in as each video lands.
  - When all have settled: if every one failed, show the error state with the first error code (today's behaviour). If only some failed, show the toast "1 of 3 didn't come through" and go back to idle. Otherwise go idle.
- `board.js`: the single `pending` tile becomes a list. `addPending(n = 1)` adds tiles; `finishPending(list)` swaps **one** pending tile for the fresh list in one render (still no count flicker); `removePending()` drops one. The count is reels plus pending tiles.
- `app.js`: wire `onMore: (n) => board.addPending(n)`. The existing `onDone` (reload the pile, `finishPending`, `player.addReels`, reveal if it already existed) now runs once per video.
- No new JS modules, no markup changes (so nothing to mirror into `watch.html`).
- Known quirk, not fixed: the pile is newest-first, so a tweet's videos show in reverse order of finishing.

### 6. Dev board, docs
- `scripts/dev_board.py`: some seeds become `Source.X` (`x.com/dev/status/…`). `FAILURE_WORDS` gains `"novideo"` → `NO_VIDEO`. The fake pipeline gets `count_videos`: a URL containing `multi` → 3. Update its docstring and `tests/test_dev_board.py` as needed.
- `README.md`: X in the intro and paste text, the fixer links, `ids` in the `POST /jobs` row, the `no_video` failure code, and that `COOKIES_FILE` can also hold x.com cookies for NSFW or protected tweets.
- `CLAUDE.md`: job flow (an X paste counts videos and makes one job per video, `Job.item` → `playlist_items`), things learned (`/video/N` counts photos; X is limited to twitter extractors so a tweet's link can't pull from other sites; trailing `t.co` stripped), dev_board's `novideo` and `multi` words.

## Verification
1. **First, a spike (before any code):** in the Docker image, run yt-dlp 2026.8.19 against one public single-video tweet and one multi-video tweet with `process=False`. This confirms that anonymous access works and that the entry counts look right. If X refuses guests, stop and discuss (bump yt-dlp, or cookies).
2. Unit tests, all offline: `.venv\Scripts\python.exe -m pytest`. New cases:
   - X hosts, fixer rewriting, and look-alike hosts rejected (`x.com.evil.org`, `notx.com`, `t.co`)
   - each new error message → code
   - `playlist_items == str(item)`
   - `allowed_extractors` present only for X URLs, and a real `YoutubeDL(opts)` for an x.com URL loads `twitter` but not `generic`
   - `count_videos` with fake playlist, single and raising YDLs, plus the cap
   - trailing `t.co` stripped
   - `submit` making N jobs with items 1..N; a repaste not counting again; the queue-room check; no counter, a timeout or an error → 1 job; non-X never counts
   - `POST /jobs` returning `ids`
   - `SOURCE_NAMES[Source.X]`
3. Page by hand: `scripts/dev_board.py` in Docker (README command). Paste an x.com link containing `multi` → 3 pending tiles fill one by one. `novideo` → "there's no video in that one." A fxtwitter link → goes through. The line reads "X · …".
4. A real download: `$env:REELS_TEST_URL = "<x.com video tweet>"; pytest -m network` inside Docker (needs ffmpeg). Then a multi-video tweet through the real app gives several reels.
